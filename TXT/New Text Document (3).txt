PHASE 2 — Product Detail: Gallery, Variants, Specs
==================================================

Goal:
Product detail must behave like a real ecommerce product page.

Required behavior:

* Large main image.
* Thumbnail gallery.
* Clicking thumbnail changes main image.
* Gallery images come from ProductImage, sorted by sortOrder.
* Variant options appear only if product has real option groups.
* Example option group:
  Màu sắc:

  * Black
  * White
  * Blaze Silver
  * Shadow White
* Example option group:
  Phiên bản:

  * Ultra Max
  * Ultimate
  * Extreme
* Selecting options resolves the correct ProductVariant.
* Selected variant updates:

  * image
  * price
  * sale price
  * stock
  * selected variantId
* Invalid/unavailable combinations are disabled.
* Quantity cannot exceed selected variant stock.
* Add to cart sends selected variantId.
* If no variants exist, hide variant selector and fallback to base product.
* If no gallery exists, show only primary image.

Technical specs:

* Add or verify ProductSpec/ProductAttribute support.
* Specs must come from DB.
* Do not hardcode specs by category.
* Only show specs with non-empty name and value.
* If no specs, hide the entire specs section.
* Keep specs sorted by sortOrder.
* Example:
  Thông số kỹ thuật:

  * Sensor: PAW3955
  * Polling Rate: 8000Hz
  * Trọng lượng: 48g
  * Kết nối: Wireless

Short specs:

* Keep shortSpecs separate from variants and technical specs.
* shortSpecs can appear on product card or near product subtitle.
* Do not use shortSpecs as purchase options.

PHASE 3 — Product Cards And Product Row Carousel
================================================

There are two different slideshow behaviors.

A. Product row carousel:
For sections such as:

* Sản phẩm tương tự
* Cùng danh mục
* Top sản phẩm bán chạy
* Sản phẩm khuyến mãi
* Homepage product rows

Behavior:

* The whole product row auto-slides horizontally.
* Desktop: auto-slide every 3–5 seconds.
* Desktop: pause row auto-slide when hovering over the row.
* Manual left/right arrows work.
* Mobile: row supports horizontal swipe.
* Do not trap vertical scroll.
* Do not auto-slide if there are too few products.
* Respect prefers-reduced-motion.

B. Individual product card image slideshow:
Desktop only:

* Card image changes only when hovering that specific card.
* primary image -> gallery image 2 -> gallery image 3 -> repeat
* Mouse leave resets to primary image.
* Other cards do not change unless hovered.

Mobile/touch:

* Disable hover image slideshow.
* Product card tap must open product detail.
* Do not make mobile tap conflict with image changing.

Shared architecture:
Create/reuse:

* getProductCardImages(product)
* useHoverImageSlideshow(images)
* ProductRowCarousel or useAutoProductRowCarousel

Image rules:

* primary image first
* galleryImages sorted by sortOrder
* remove duplicate URLs
* remove empty/invalid URLs
* do not fetch extra images on hover
* do not hardcode image arrays
* no layout shift

Apply to:

* /products product cards
* related product cards
* homepage product cards
* promotion/best-seller sections

PHASE 6 — Admin Product Management
==================================

Goal:
Admin product management must be usable, not just visually nice.

Product category filter:

* Primary area:
  "Khu vực quản lý sản phẩm"
* Categories from DB, not hardcoded except "Tất cả".
* Example:
  Tất cả · 31 sản phẩm
  Chuột · 8 sản phẩm
  Tai nghe · 7 sản phẩm
  Màn hình · 5 sản phẩm
* Clicking category filters product list.

Brand filter:

* Secondary area:
  "Lọc theo thương hiệu"
* "Tất cả hãng" should show number of distinct brands, not total products.
  Example:
  Tất cả hãng · 11 hãng
* Individual brand chips show product count:
  Akko · 2 sản phẩm
  Razer · 5 sản phẩm
* Do not show ambiguous badge-only numbers.
* Category + brand + status + search must combine.

Admin product form:
Separate these concepts:

1. shortSpecs:

   * displayed on product card/subtitle
   * example: HERO 2, Wireless, 60g

2. purchase options / variants:

   * customer-selectable
   * example:
     Màu sắc: Black, White, Blaze Silver
     Phiên bản: Ultra Max, Ultimate
   * saved using ProductOption/ProductOptionValue/ProductVariant
   * variants have SKU, price, salePrice, stock, imageUrl, active

3. technical specs:

   * table on product detail
   * example:
     Sensor: PAW3955
     Polling Rate: 8000Hz
     Trọng lượng: 48g

Admin UI must support:

* add/remove/reorder gallery images
* add/remove option groups
* add/remove option values
* create/edit variant rows
* add/remove technical spec rows
* save nested data using Prisma transaction
* validate input
* no raw JSON textarea as main UX

PHASE 7 — Reviews And Rating Correctness
========================================

Rules:

* No fake reviews.
* No Math.random reviews.
* No hardcoded review count like "(12)".
* Product card rating/count must come from real Review records only.
* If no reviews:
  reviewCount = 0
  averageRating = null or 0
  hide rating row or show "Chưa có đánh giá".
* Product detail with no reviews:
  "Chưa có đánh giá nào cho sản phẩm này."

Review submission:

* Only authenticated users can review.
* User must have completed/delivered order containing that product.
* User cannot duplicate review for same product-order.
* If Review model links to Order, verify product exists inside OrderItem.
* Better if linking to OrderItem is feasible, but do not over-rewrite if current implementation is already safe.
